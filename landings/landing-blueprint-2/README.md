# Landing Blueprint

Воспроизводимый пайплайн для лендингов "квиз-калькулятор + AIDA + email/CRM
бэкенд" — обобщение того, что реально собрано и протестировано для
типографии «Цифра» (Ижевск, мерч-оффер).

## Быстрый старт

```bash
node render.js config.example.json dist/
cd dist/backend && npm install
BITRIX_WEBHOOK_URL="..." SMTP_HOST="..." SMTP_USER="..." SMTP_PASS="..." node server.js
```

Открыть `dist/index.html` любым сервером статики (или просто в браузере —
формы работают через fetch на `/api/...`, для реального теста форм нужен
запущенный `dist/backend/server.js` и статика, отданная тем же процессом
или через reverse-proxy).

## Как использовать для нового клиента (агентный workflow)

1. Прочитать `SKILL.md` — это инструкция для агента (шаги 0-8)
2. Дать агенту URL/файлы клиента
3. Агент вытаскивает факты, спрашивает про пробелы, собирает `config.json`
   по образцу `config.example.json`
4. `node render.js config.json dist-<client>/`
5. Прогнать `reference/fact-checking-checklist.md`
6. Сдать zip клиенту

## Структура

```
SKILL.md                        — методология для агента
config.example.json             — образец конфига (данные «Цифры», урезанный каталог)
render.js                       — рабочий скрипт сборки (config → dist/)
reference/
  aida-block-map.md             — какие блоки, когда добавлять/убирать
  quiz-calculator-pattern.md    — когда нужен квиз, как он устроен
  fact-checking-checklist.md    — обязательный чек-лист перед сдачей
templates/
  index.template.html           — 9 AIDA-блоков с {{плейсхолдерами}} и <!--маркерами-->
  styles.template.css            — дизайн-система, бизнес-независима, копируется как есть
  script.template.js             — универсальный движок квиза (3 плейсхолдера всего)
  backend/
    server.template.js           — email (nodemailer) + CRM (Bitrix24-подобный webhook),
                                    Promise.allSettled, честный 502 при отказе обоих каналов
    package.json
```

## Проверено (не просто написано — прогнано)
- `render.js` реально собирает рабочий `dist/` из `config.example.json`
- Fail-fast на неполном конфиге (не рендерит мусор с пустыми полями)
- Сгенерированный `backend/server.js` проходит `node --check` и живой
  curl-тест: health, honeypot, честный 502 при недоступности обоих каналов
- Ни одного незамещённого `{{...}}` или `<!--MARKER-->` в выходном HTML

## Известные ограничения (см. также комментарий в шапке render.js)
- Экранирование в render.js — только `& < >`, для кавычек в атрибутах при
  недоверенном вводе в config нужно усилить
- Под другую CRM (не Bitrix24-подобный webhook) — переписать
  `createBitrixLead` в `backend/server.template.js` по образцу
- Дизайн (styles.template.css) — конкретная дизайн-система «Цифры»
  (зелёно-бумажная палитра, Unbounded+Manrope). Для другого бренд-стиля —
  либо менять CSS-переменные в шапке файла, либо подключить theme-factory.

  реквизиты оператора ПДн: идут в футер и в новую страницу `privacy.html`

- Чекбокс согласия на обработку ПДн — теперь реальный `required`-чекбокс с

- Cookie-баннер (`templates/script.template.js: initCookieConsent`) — Яндекс.Метрика
  стартует только после нажатия «Принять», до этого — не ставит cookie
- JSON-LD `LocalBusiness` + `FAQPage` — генерируются из `config.contact`/`config.faq`
  автоматически, для обычного SEO и для ответов нейросетей (GEO/AEO)
- Без `legalEntity`/`mapEmbedUrl` в конфиге — честный `TODO` в HTML и warning
  в консоли рендера, сборка не падает (обратная совместимость с `config.example.json`
  проверена)

## Известные ограничения v1.2
- `privacy.template.html` — минимальный, но не заменяет юридическую проверку
  реальным юристом; это разумная заготовка, не готовый к печати документ
- Cookie-баннер простой (accept-only, без гранулярного согласия по категориям
  cookie) — для small-business лендинга этого обычно достаточно, для более
  строгих случаев (b2b с юрлицами-партнёрами из ЕС и т.п.) нужен более
  детальный баннер

## v1.3 — дизайн-токены (JetBrains Mono / чёрно-зелёная палитра)
Применены присланные токены (`font.family`, цвета, radius/shadow/motion scale).
Имена CSS-переменных НЕ менялись (--brand-green, --forest-900 и т.п.) — только
их значения, чтобы не трогать 300 строк CSS построчно.

Сознательное отступление от буквальных токенов (см. комментарий в
styles.template.css): `font.lineHeight.base=14px` при `font.size.base=14px`
даёт межстрочный интервал 1.0 — для текста абзацами это нечитаемо (строки
слипаются). Для body применён line-height 1.5, 14px-значение буквально оставлено
только там, где уместно (однострочные UI-элементы). Если 1.0 — осознанный
выбор для плотного интерфейса, а не артефакт скрейпинга — верните его явно.

Токены spacing-scale (`space.1..8`) и shadow/motion добавлены как CSS-переменные
(`--space-1`…`--space-8`, `--shadow-1`…`--shadow-4`, `--motion-instant`…`--motion-slow`),
но НЕ применены ко всем 300 строкам существующего CSS — только к pill-радиусам
(заменены на `--radius-pill`) и к новым блокам (cookie-баннер, карта). Полная
ретрофит-замена всех отступов/теней под новую шкалу — отдельная задача.

## v1.4 — WordPress-экспорт (Astra+Spectra) и третий канал доставки лида
- `node render-wp.js config.json dist-wp/` — та же конфигурация, что и для
  статического сайта, но на выходе `content.html` с core-блоками WordPress
  (`wp:heading`, `wp:paragraph`, `wp:columns`, `wp:buttons`, `wp:image`) —
  готов для WP All Import в поле `post_content`. Квиз-калькулятор идёт одним
  `wp:html`-блоком с тем же движком внутри (не редактируется визуально в WP,
  но гарантированно работает после импорта — см. обоснование решения в шапке
  `render-wp.js`).
- **Важно для продакшен-конфигов**: `hero.photo` / `catalog.items[].img` для
  WP-экспорта должны быть реальными `https://` ссылками на картинки с
  донор-страницы (не data-URI, как в демо-примере) — WP All Import умеет
  скачивать картинки из `wp:image` блока в медиатеку именно по прямому URL.
- Перед пакетным импортом десятков лендингов — протестируйте ОДИН вручную
  (render-wp.js выводит это предупреждение явно при каждом запуске).
- `GENERIC_WEBHOOK_URL` — третий канал доставки лида в `backend/server.js`,
  независимый от Bitrix24/почты (для Zapier/Make/любой CRM с JSON-POST приёмом,
  пока конкретная CRM не выбрана). Протестирован живым curl-запросом.

## v1.5 — реальный ресёрч по Spectra/Astra/WP All Import
`reference/wordpress-spectra-astra-risks.md` — главный риск найден: импорт
блоков Spectra в обход редактора Gutenberg (ровно то, что делает WP All
Import) с высокой вероятностью НЕ генерирует их CSS на фронтенде — три
независимых источника подтверждают один и тот же паттерн отказа. Это задним
числом обосновывает решение `render-wp.js` использовать в основном core-блоки
WordPress, а не блоки `uagb/*` — у core-блоков этой проблемы нет архитектурно.
