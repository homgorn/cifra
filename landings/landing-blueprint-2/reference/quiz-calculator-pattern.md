# Паттерн «квиз-калькулятор» (референс)

Когда использовать: у бизнеса есть каталог из нескольких категорий товаров/
услуг, и внутри каждой — параметры, которые реально влияют на стоимость
(тираж, объём, сложность, срочность), но НЕТ фиксированного прайса на все
комбинации (иначе это просто прайс-таблица, квиз не нужен).

## Гибридный случай (найден на реальном тесте, цифра18.рф/catalog/suvenirnaya-produktsiya/)
Бывает третий вариант: у части позиций каталога ЕСТЬ открытая цена "от X ₽/шт"
на базовое исполнение (без тиража/кастомизации), а финальная стоимость всё
равно требует расчёта. В этом случае НЕ убирать квиз — открытая цена работает
как крючок доверия в блоке 4 (каталог), а квиз в блоке 6 считает точную
стоимость под тираж/макет/срочность. `config.catalog.groups[].items[].priceFrom`
(строка, например `"от 15 ₽/шт."`) — опциональное поле именно под этот случай,
не путать с полным прайс-листом (там цена есть на ВСЕ комбинации, и тогда
блок 6 не нужен вообще, см. правило выше).

## Шаги визарда (4 шага — проверенный оптимум)
1. Категория — карточки, обычно 3-6 штук
2. Товар/услуга внутри категории — карточки с фото/иконкой и методом
3. Параметры заказа — общие для всех категорий поля: количество/объём (число),
   готовность к производству (макет есть / нужна разработка), срочность
   (стандартный срок / горит), свободное текстовое поле "пожелания" — сюда
   идёт всё, что не удалось формализовать, БЕЗ выдумывания фиксированного
   списка опций, если в исходнике его нет
4. Контакты — имя, телефон (обязательно), email (опционально) + сводка
   выбранного + кнопка "получить расчёт" (не "купить")

## Технические принципы
- Состояние — один объект `state` в замыкании, рендер — чистые функции от state
- Прогресс-бар и индикаторы шагов обновляются одной функцией `goToStep(n)`
- Honeypot-поле (`website`) — на КАЖДОЙ форме
- Валидация телефона — по количеству цифр (10-12), не строгий regex формата
- Финальный шаг — читаемая сводка выбранного перед отправкой
- Рядом с кнопкой отправки — mailto-фолбэк с предзаполненным письмом из тех
  же данных state, чтобы форма не была единственным каналом

## Backend-контракт
- Отдельный POST-эндпоинт для квиза (свой текст письма/лида), общая
  инфраструктура валидации/rate-limit с простой формой
- Минимум два канала доставки, Promise.allSettled, честный 502 если ВСЕ упали
- Канал, который не настроен, должен бросать ошибку, а не возвращать null —
  иначе Promise.allSettled засчитает его как успех, и лид потеряется без
  единого следа в логах (реальный баг, пойманный тестом на первой версии
  этого блюпринта)
