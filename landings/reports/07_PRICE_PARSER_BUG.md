# Ошибка парсера цен: каждой позиции приписывалась чужая цена

Дата: 2026-10-04. Найдена при сборке первого лендинга, до него никто
не замечал. Разбор с доказательствами, потому что выводы из неё
меняют цифры во всём проекте.

## Что было сломано

`fetch_catalog.py` искал цену товара так: сначала пять CSS-селекторов,
а если ни один не совпал, то regex по всему тексту страницы.

```python
if not price_txt:
    m = re.search(r"от\s+[\d\s\xa0]+\s*₽\s*/\s*[^\s,]+", soup.get_text(" "))
```

Второй путь срабатывал всегда, потому что на странице товара есть цены
чужих товаров. В шапке сайта стоит блок «Избранные товары», и в выдаче
`get_text()` он идёт раньше карточки самого товара.

## Почему это не выглядело как ошибка

Значение получалось правдоподобным: «от 0 ₽/шт.», «от 40 ₽/шт.». И оно
было одинаковым почти на всех страницах, потому что бралось из одного и
того же блока избранного.

Вывод в выгрузке при этом выглядел безобидно:

```
Разобрано 180, с ценой 0
```

Ноль выглядит как «цен на сайте нет». На самом деле цены были, просто
чужие. Число `0` в поле `value` неотличимо от «цены не задано», и
`parse_price` для обоих случаев даёт одно и то же.

## Что показала проверка

На странице календаря 2027 «Бизнес» найдено 36 знаков рубля. Вот откуда
они берутся:

| Блок на странице | Что это | Цена |
|---|---|---|
| `div.header__favorites` | Избранные товары в шапке | от 0 ₽, от 40 ₽, от 240 ₽, от 15 ₽, от 0 ₽, от 350 ₽ |
| `span.price-per-pc` в `div.product-calculate` | Калькулятор тиражей ЭТОГО товара | 360, 330, 290, 270, 250, 230, 210 ₽ |

Парсер брал первое. То есть у календаря 2027 стояла цена ROLL-UP.

## Почему селекторы не совпали

Они искали классы шаблона `cifra_new`: `.catalog-item__price`,
`.product-price`, `[itemprop=price]`. На сайте используется другой шаблон:

```
product / product-gallery / product-tabs / product-calculate
```

Ни один из пяти селекторов не находит ни одного элемента, то есть
фолбэк был не запасным путём, а единственным рабочим. И он был неправильным.

Это подтверждало опасение из 02_DECISIONS.md раздел 8: парсер был
написан под шаблон `cifra_new` и проверен на одной странице из
семисот. Оказалось, что не на одной, а ни на одной.

## Как исправлено

1. Селекторы переписаны под фактический шаблон. Цена берётся только
   из `.product-calculate` карточки товара.
2. Фолбэк по всему тексту страницы удалён совсем. Он не может быть
   правильным: на странице всегда есть чужие цены.
3. Добавлена лестница тиражей `extract_price_tiers`. Это данные с сайта:
   20 шт по 360 ₽, 50 по 330, 100 по 290, 200 по 270, 300 по 250,
   500 по 230, 1000 по 210.
4. Поле `price.source` записывает, откуда взято значение. У пустой цены
   источник записан явно: «нет калькулятора на карточке».

## Проверка, что лестница настоящая, а не дефолт сайта

Одинаковые числа у разных товаров выглядели подозрительно: лестница
360/330/290/270/250/230/210 была у шести разных календарей. Проверено
сравнением трёх страниц:

| Позиция | Лестница |
|---|---|
| Бизнес 3 рекламных поля 2027 | 20=360, 50=330, 100=290, 200=270, 300=250, 500=230, 1000=210 |
| PREMIUM 1 рекл. поле неон | 20=360, 50=330, 100=290, 200=270, 300=250, 500=230, 1000=210 |
| PREMIUM прозрачный пластик 3 поля | 20=985, 50=812, 100=766, 200=731 |

У прозрачного пластика своя лестница, значит числа приходят из карточки
конкретного товара, а не из общего дефолта. Совпадение у первых двух
означает, что у клиента для этих позиций одна ценовая таблица, и это
его данные, а не ошибка парсера.

## Найденная аномалия в данных сайта

У «Календаря карманного» лестница такая:

```
512 шт = 14 ₽/шт,  1000 шт = 50 ₽/шт
```

Цена за штуку растёт с тиражом. Это, скорее всего, ошибка данных на
стороне клиента. На лендинг цены не публикуются, вопрос передан
заказчику, запись в `config.json` → `sources.knownAnomalies`.

## Что это значит для остального проекта

**Все ранее выкачанные цены, кроме калькулятора товара, были неверны.**
То есть любая цифра, взятая из выгрузки до 2026-10-04, требует
перепроверки по источнику. Проверка сайта в 06_SITE_VERIFICATION.md
делалась вручную по страницам и потому верна: числа «от 240 ₽/шт.» и
«от 15 ₽/шт.» оттуда и взяты, а не из выгрузки.

Главный урок шире парсера: **фолбэк, который ищет значение по всему
тексту страницы, не может считаться проверяемым.** На странице товара
всегда есть цены других товаров. Если данные не удалось найти точно,
правильный ответ «нет данных», а не «нашёл похожее».
