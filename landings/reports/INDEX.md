## Сборка с нуля: четыре шага, порядок обязателен

```powershell
python landings\_scrape\fetch_catalog.py --parse-only
python landings\_scrape\fetch_images.py --section kalendari --out landings\kvartalnyy-kalendar-2027\assets
python landings\_scrape\optimize_images.py --src landings\kvartalnyy-kalendar-2027\assets --dst landings\kvartalnyy-kalendar-2027\assets\web
python landings\_scrape\build_calendar_config.py

cd landings\landing-blueprint-2
node render.js ..\kvartalnyy-kalendar-2027\config.json ..\kvartalnyy-kalendar-2027\dist

cd ..\..
python landings\validate_landing.py landings\kvartalnyy-kalendar-2027
```

Последняя команда обязательная: пока она падает, публиковать нельзя.

## Проверка собранного лендинга

`python landings/validate_landing.py <папка>`, 16 гейтов. Ловят
незамещённые плейсхолдеры, заглушку счётчика Метрики, цены при
`showPrices: false`, рассинхрон id между HTML и JS, битые якоря,
отсутствие юридического слоя, em-dash в видимом тексте,
неэкранированные кавычки, дубли id, отсутствующие фотографии.

## Три правила этой папки

1. **Каждое утверждение о факте ссылается на источник.** Файл
   сайта, выгрузка, дата. Без источника утверждение не пишется.
2. **Что опроверено и что нет, помечено явно.** Раздел «Где я не
   уверен» есть в каждом документе, где есть неопределённость.
3. **Правка генератора, а не артефакта.** Собранный `dist`
   правится через конфиг, иначе правка потеряется при следующей
   сборке.

## Чего в папке нет и почему

- **Готовых к публикации лендингов.** Первый собран, но падает гейт 8:
  нет реквизитов оператора персональных данных. Публиковать рано.
- **`php/lead.php`.** Файл не написан, есть спецификация в
  `03_INSTRUCTIONS.md` часть 3. Написать непроверяемый код и отдать
  его как готовый нельзя, в проекте это прямо запрещено.
- **Второй половины каталога.** Обход умер на 180-й странице из 457
  на таймаутах. Для первого лендинга хватило, для мерча данных нет.
- **Превью лендингов на сайте отчёта.** Появится после снятия
  блокера с реквизитами.
