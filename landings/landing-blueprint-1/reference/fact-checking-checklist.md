# Чек-лист фактчекинга перед сдачей лендинга

Прогонять на КАЖДОМ новом лендинге из этого блюпринта — не по желанию.

## Контент
- [ ] Каждый пункт каталога/цен/УТП сверен с исходником — указан источник
- [ ] Ни одного выдуманного отзыва, кейса или клиента
- [ ] Ни одной ссылки на мессенджер/соцсеть, которую не видел вживую
      (ссылка по номеру телефона типа wa.me/номер — ОК, это протокол WhatsApp,
      подтверждения аккаунта не требует)
- [ ] Цифры доверия (лет на рынке, кол-во клиентов) — с исходником, иначе блок
      урезается до подтверждённого
- [ ] Чего не хватает (соцсети, конкретные цвета/материалы, точный SLA) —
      явный TODO в коде + пункт в CHANGELOG. Никогда не заполнять правдоподобной
      выдумкой вместо факта.

## Код
- [ ] `node --check` на всех .js файлах
- [ ] Кросс-проверка ID между HTML и JS — нет висячих getElementById
- [ ] Живой тест backend: health-check, провал валидации, honeypot (бот =
      "успех" без создания лида), обрыв ОБОИХ каналов доставки — ожидаем
      честный 502, не молчаливый ok:true

      тире (—) бьются в кодировке чаще всего
- [ ] Rate-limit и honeypot есть на каждом POST-роуте
