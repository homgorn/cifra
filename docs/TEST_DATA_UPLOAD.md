# Тестовые папки в репозиторий: как правильно (до 50 MB)

Коротко: **да, загружать тестовые папки можно**, но только маленький сэмпл.

## Рекомендация
- Держать тестовый набор в пределах **до 50 MB на файл** и небольшого общего объема.
- Основной массив (гигабайты) в git не класть.

## Почему
- GitHub hard-limit на один файл: 100 MB.
- Большие бинарники сильно раздувают историю репозитория.

## Как собрать тестовый набор автоматически
Используйте скрипт `scripts/prepare_test_dataset.py`:

```bash
python3 scripts/prepare_test_dataset.py \
  --source-root "/path/to/your/photo-root" \
  --output-dir sample_data \
  --max-mb 50 \
  --max-per-folder 10
```

### Если хотите только конкретные категории
```bash
python3 scripts/prepare_test_dataset.py \
  --source-root "/path/to/your/photo-root" \
  --output-dir sample_data \
  --max-mb 50 \
  --max-per-folder 15 \
  --include-folders "БЕЙДЖ" "ВИЗИТКИ" "РУЧКИ, БЛОКНОТЫ"
```

Скрипт:
- копирует изображения в `sample_data/` с сохранением структуры;
- создает `sample_data/manifest.json` с перечнем файлов и размеров;
- останавливает выбор по лимиту размера.

## Что коммитить
- `sample_data/` (если действительно нужен тестовый набор в репо);
- `sample_data/manifest.json` обязательно.

## Что не коммитить
- Полный архив с прод-данными;
- Кэши моделей и временные файлы.
