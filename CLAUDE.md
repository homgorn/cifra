## Гейты перед done
Все шесть обязательны. Каждый ловит свой класс ошибок, ни один не заменяет
остальные:

| Гейт | Что ловит |
|---|---|
| `validate_report.py` | битые ссылки, отсутствующие файлы, em-dash, нумерация страниц, навигация, состав футера |
| `validate_theme.py` | цветовые литералы вместо токенов, вторая тема, контраст ниже порогов WCAG |
| `check_layout.py` | раскладку и графики в браузере: размеры канвасов, переполнение, элементы вне контентной колонки, ошибки JS |
| `smoke_wm_js.js` | целостность данных в `wm-data.js` |
| `validate_worker.py` | вес воркера в лимите 1 МиБ |
| `shots.py` | скриншоты обеих схем для визуальной проверки глазами |

Числовых проверок недостаточно: страница может пройти все пять гейтов и
выглядеть разобранной. Видно только рендером, поэтому `check_layout.py`
обязателен для всего, что трогает CSS или графики.

## Правила отчёта клиенту
- Нейтральный тон: без имени клиента, без обращения по имени, без первого лица.
- Только Яндекс как источник инструментов. Google-трафик упоминать честно
  как факт, но не строить на нём инструменты.
- Без em-dash в MD, HTML и JS.
- Все числа на сайте и в отчётах берутся из данных скриптом. Руками не вбивать.
  Скрипты, которые переписывают текст страницы, обязаны быть идемпотентными.
- Батники только ASCII: кириллица без BOM ломает cmd.
- Секреты только в `.env`, не в коде и не в чате.
- Счётчики Метрики разведены: сайт `METRIKA_COUNTER_ID`, карточка в Картах
  `METRIKA_MAPS_COUNTER_ID`.

## Lessons: что уже сломали и как ловится

**Цветовые литералы в компонентах ломают тему.** В `main.css` был блок
`prefers-color-scheme: light`, а шапка брала литерал `rgba(10, 14, 20, 0.9)`.
На светлой схеме ОС тело становилось белым, шапка оставалась тёмной, и логотип
с меню были нечитаемы. Ловит `validate_theme.py`: литерал цвета вне `:root`
и блока печати, либо блок `prefers-color-scheme` с токенами.

**Один и тот же тёмный тон в двух местах ловится тем же способом.** Оверлей
поиска был `rgba(5, 8, 12, 0.86)` поверх уже тёмной страницы, и поиск
выглядел чёрным провалом. Полупрозрачные поверхности держать в токенах:
`--surface-header`, `--overlay-bg`.

**Фиксированная высота графика не масштабируется вместе с данными.**
`.chart-container` был 300px на все случаи. Как только кластеров стало 22
вместо 8, полосы начали наезжать друг на друга, а Chart.js стал пропускать
подписи оси: бары и подписи разъехались. Теперь `mk()` в `main.js` считает
высоту от числа полос и запрещает `autoSkip` на оси Y.

**Имя функции перебивается переменной в том же теле.** `function palette()`
молча ломалась `var palette` ниже по коду: `palette is not a function`, и все
графики страницы падали. Ловит `check_layout.py`, потому что он слушает
ошибки JS в браузере. `node --check` такой баг не видит: синтаксис валиден.

**Ширина графика по умолчанию 300x150 означает, что Chart.js не подхватил
контейнер.** Ловит `check_layout.py`: канвас меньше 120x60 считается
недоделанным.

**Кластеризация не равно релевантность.** Кластер отвечает на вопрос «о чём
фраза», но не «наша ли она». Проверять надо отдельно, и порядок проверок
важен: сначала маркер услуги, потом чужие отрасли, иначе «визитки для
стоматолога» вылетают как запрос к стоматологу. Сборки Topvisor строятся
скриптом `filter_topvisor_queries.py` в три корзины, ничего не удаляется
молча.

**Регулярка с `\w*` по кириллице ловит соседние слова.** `ижевс\w*` в
правиле опечаток матчило «ижевск» и выкидывало 400 живых фраз, потому что
внутри кириллического слова нет границы для `\b`. Мусор распознавания
сопоставлять по целым токенам через множество.

**Секция в разметке, вставленная один раз, больше не обновляется.** Карта
отчёта `#toc` на главной и описание страницы в реестре навигации разошлись
с числами, потому что пересобирались только при первом запуске. Любой
блок, который вставляется скриптом, должен пересобираться целиком при
каждом запуске, а не «если его ещё нет».
