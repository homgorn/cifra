# Проект: ЦИФРА18, SEO + GEO продвижение

## Суть
Комплексное SEO и GEO продвижение типографии «Цифра» (Ижевск). Цель: рост
органического трафика в 3-5 раз за 6-9 месяцев, рост заявок и продаж.
Домен: цифра18.рф (punycode xn--18-6kc5a3bxam.xn--p1ai). CMS: 1С-Битрикс 23.300.

## Тип
hybrid (dev + content + automation + marketing)

## Домен
Полиграфия, широкоформатная печать, мерч, сувенирка, B2B локальный
(Ижевск и Удмуртия) с элементами B2C.

## Метрика успеха
- Органический трафик: база TBD, x3 за 6 месяцев, x5 за 12
- Небрендовые клики: x4 и x8
- Заявки из органики: x3 и x5
- Видимость в ответах ИИ: 0, затем Top-3, затем Top-1
- Страниц в индексе: 95% и 98%

## Стандарты
- Все измерения берутся из данных. Число, которое можно посчитать,
  считается скриптом, а не вписывается руками
- У каждого числа есть знаменатель. «390 в ТОП-10» бессмысленно без
  «из 535 строк выгрузки» или «из 492 реальных запросов»
- Один фикс в шаблоне Bitrix это исправление на сотнях страниц
- Контент: human-first, экспертный, факточекинг, без em-dash
- GEO: llms.txt, JSON-LD, доступ ИИ-роботам, citability score
- Каждый тикет закрывается проверкой на настоящем артефакте, а не
  рассуждением о нём

## Статус
**Этап:** аудит закончен, отчёт собран и опубликован, идёт сбор позиций
и решение по семантике.
**Сайт отчёта:** `reports/cifra18-audit/`, 27 страниц, 62 графика, живёт
на `https://homgorn.github.io/cifra/`. Публикуется коммитом в ветку
`gh-pages` через `git subtree push`: Actions на этом аккаунте не выдаёт
раннер, job падает с нулём шагов.
**Клиентский отчёт:** `CLIENT_REPORT.md` и `CLIENT_REPORT.docx`, собирается
скриптом `build_client_report.py` из данных.
**Остаток упирается в действия владельца, не в код:**
1. Выпустить новый токен Яндекса со scope `EXTERNAL_LINKS`, без него
   недоступны данные по внешним ссылкам
2. Загрузить 606 новых фраз из `topvisor/exports/import_queries.csv`
3. Разобрать 167 фраз из `review_queries.csv`
4. Прислать выгрузку CRM, без неё нельзя посчитать выручку по каналам
5. **Секрет приложения Яндекса скомпрометирован**, см. раздел Lessons

## Гейты перед done
Все обязательны. Каждый ловит свой класс ошибок, ни один не заменяет
остальные. Точка входа: `python scripts/export/validate_report.py`.

| # | Гейт | Что ловит |
|---|---|---|
| 1-9 | `validate_report.py` | битые ссылки, отсутствующие файлы, em-dash, нумерация страниц, навигация, состав футера, канвасы против `mk()`, локальный сервер, целостность данных |
| 10 | `validate_theme.py` | цветовые литералы вместо токенов, вторая тема, контраст ниже порогов WCAG |
| 11 | `check_layout.py` | раскладку и графики в браузере: размеры канвасов, переполнение, элементы вне колонки, ошибки JS |
| 12 | `sync_cluster_counts.py` | числа в документах против чисел в данных |
| 13 | `build_client_report.py --check` | что блоки отчёта собраны из данных, а не вписаны руками, и что в отчёте нет em-dash |
| 14 | `plural()` в `facts.py` | инвертированное русское склонение |
| 15 | счётчик Метрики | что числа собраны по счётчику сайта, а не карточки в Картах |
| 16 | `smoke_wm_js.js` | целостность данных в `wm-data.js` |
| 17 | `validate_worker.py` | вес воркера в лимите 1 МиБ |
| 18 | `shots.py` и `shots_live.py` | скриншоты обеих схем, локально и на живом сайте |

Числовых проверок недостаточно: страница может пройти все гейты и
выглядеть разобранной. Видно только рендером, поэтому `check_layout.py`
обязателен для всего, что трогает CSS или графики.

## Правила отчёта клиенту
- Нейтральный тон: без имени клиента, без обращения по имени, без первого лица
- Только Яндекс как источник инструментов. Google-трафик упоминать честно
  как факт, но не строить на нём инструменты
- Без em-dash в клиентских MD, HTML и JS. Не заменять тире регуляркой:
  оно стоит связкой, двоеточием и маркером списка, и слепая замена даёт
  «После, масштабирование»
- Все числа на сайте и в отчётах берутся из данных. Скрипты, которые
  переписывают текст, обязаны быть идемпотентными
- Батники только ASCII: кириллица без BOM ломает cmd
- Секреты только в `.env`, не в коде, не в коммитах, не в чате
- Счётчики Метрики разведены: сайт `METRIKA_COUNTER_ID` (50863157),
  карточка в Картах `METRIKA_MAPS_COUNTER_ID` (59102713). У числа должен
  быть записан счётчик, иначе это не число

## Lessons: что уже сломали и как ловится

**Em-dash проезжает мимо гейта, если гейт смотрит в одно место.**
Проверка искала знак только в `main.js`, а `site-data.js` собирается
отдельным скриптом, и знак стоял там. Теперь файл проверки берётся с
диска, а не из списка. Ловит `validate_report.py` шаг 2.

**Число без знаменателя это half-правды.** «390 запросов в ТОП-10»
выглядело нормально. На 535 строках выгрузки 390, на 492 реальных
запросах 359, процент одинаковый, 73. Клиент сверяет два документа и
находит расхождение. Правило: у каждого числа есть знаменатель, и он
пишется рядом.

**Два числа процента от разных знаменателей читаются как противоречие.**
Индексация считается и от всех страниц, известных роботу (252 из 2423,
10,4%), и от проверенной выборки (142 из 717, 19,8%). Оба верны. Без
таблицы «от чего считано» один из них выглядит как ошибка.

**Синхронизатор, который ищет запрещённое число, пропускает любое
другое.** Гейт ловил литерал «8 групп». Скажи документу «23 группы», и
он остаётся зелёным. Правильный гейт идёт от факта к месту в тексте:
где стоит «запросов», там должно быть `core_queries`. Ловит
`sync_cluster_counts.py`.

**Правка артефакта вместо правки генератора откатывается следующей
сборкой.** `sync_cluster_counts.py` подставлял числа в готовый HTML, а
`build_plan3m.py` держал ту же фразу строкой в коде. Перезапуск
генератора возвращал «8 групп». Теперь числа берёт `facts.py`, а
генератор только собирает текст.

**Два числа из разных множеств, склеенные в одну фразу, дают правдоподобную
неправду.** «627 запросов по 22 группы»: 627 это пул импорта в Topvisor
из двух источников, 22 это кластеры ядра. Оба числа верные, вместе они
не значат ничего. Ловит `sync_cluster_counts.py`.

**Русское склонение легко инвертируется и не падает.** `plural()` с
условием `2 <= n % 10 <= 4 and 12 <= n % 100 <= 14` даёт «2 запросов» и
«12 запроса», то есть ровно наоборот. Такая ошибка не бросает исключение,
она тихо печатает неграмотный текст клиенту. Проверяется таблицей из 14
случаев в `validate_report.py`, шаг 14.

**Ручная выгрузка из панели не несёт счётчика.** Файлы в `metrika/`
оказались выгрузкой карточки в Яндекс Картах: 79 002 визита вместо
21 110. Дальше эти числа уехали в `site-data.js` как «визиты сайта», и
ошибка была не видна, потому что сравнивать было не с чем. Теперь
счётчик объявляется в `metrika/COUNTER`, выгрузка карточки кладётся в
`exports/maps_card/`, а сайт собирается из API-среза, где счётчик
записан при выгрузке. Проверяется в трёх местах, включая гейт 15.

**Измерение в API может прийти без идентификатора.** В `source_month`
измерение даты это просто строка без `id` и без `icon_type`. Поиск по
ключу `date` отсекает всё, счётчик молча даёт ноль, и это выглядит как
«данных нет». Ключи измерений читаются, а не угадываются.

**Вставка по образцу silently делает ноль, если образца нет.**
`build_nav.py` вставлял `search.js` заменой сразу после тега `nav.js`.
Страница, собранная генератором с нуля, тега `nav.js` не содержит,
замена не срабатывает, и страница остаётся без поиска: меню на месте, а
не работает. Каждый тег проверяется отдельно.

**Скрипт, собирающий данные, врёт в своём же докстринге.**
`build_plan3m.py` утверждал, что руками не вбито ничего, и держал семь
захардкоженных чисел в таблице. Правдоподобный докстринг опаснее
отсутствия докстринга: он снимает вопрос «а откуда это число».

**Внутренняя функция перебивается переменной в том же теле.**
`function palette()` ломалась `var palette` ниже по коду, и все графики
страницы падали. `node --check` такой баг не видит, синтаксис валиден.
Ловит `check_layout.py`, потому что он слушает ошибки JS в браузере.

**Фиксированная высота графика не масштабируется вместе с данными.**
`.chart-container` был 300px на все случаи. Кластеров стало 22 вместо
8, полосы начали наезжать, Chart.js стал пропускать подписи оси.
Теперь `mk()` считает высоту от числа полос и запрещает `autoSkip`.

**Канвас 300 на 150 означает, что Chart.js не подхватил контейнер.**
Ловит `check_layout.py`: канвас меньше 120 на 60 считается недоделанным.

**Кластеризация не равно релевантность.** Кластер отвечает на вопрос
«о чём фраза», но не «наша ли она». Сначала маркер услуги, потом чужие
отрасли, иначе «визитки для стоматолога» вылетают как запрос к
стоматологу. Корзины `import_queries.csv`, `review_queries.csv`,
`blocked_queries.csv`, ничего не удаляется молча.

**Регулярка с `\w*` по кириллице ловит соседние слова.** `ижевск\w*`
в правиле опечаток матчило «ижевск» и выкидывало 400 живых фраз:
внутри кириллического слова нет границы для `\b`. Мусор сопоставлять по
целым токенам через множество.

**Секция в разметке, вставленная один раз, больше не обновляется.**
Карта отчёта и описание страницы в реестре разошлись с числами, потому
что пересобирались только при первом запуске. Любой блок, который
вставляется скриптом, пересобирается целиком при каждом запуске.

**Обещание в приложении к отчёту проверяется клиентом.** «200+ пробелов»
в файле, где 56 строк. Описание файла это тоже утверждение о фактах, и
оно проверяемо: файлы можно открыть и пересчитать.

## Слои данных и кто что читает
Ответ на вопрос «откуда взялось это число» всегда один из трёх:

| Слой | Что лежит | Кто читает |
|---|---|---|
| `data/exports/` | сырые выгрузки API, счётчик в `_index.json` | экспортные скрипты |
| `wm-data.js`, `site-data.js`, `dash-data.js` | посчитанные агрегаты | страницы сайта |
| `facts.py` | именованные факты со знаменателями | генераторы текстов, гейты |

`facts.py` печатает все факты разом: `python scripts/export/facts.py`.
Если число на сайте не находится в этом выводе, оно откуда-то ещё, и
это повод найти источник.

## Быстрые команды
```
python scripts/export/facts.py                  # все числа проекта с источниками
python scripts/export/validate_report.py        # все гейты, точка входа
python scripts/export/build_client_report.py    # пересобрать отчёт клиенту
python scripts/export/sync_cluster_counts.py    # проверить числа в документах
refresh_all.bat                                # полный цикл: API, данные, гейт, деплой
refresh_all.bat --data                         # только API и данные, без деплоя
refresh_all.bat --site                         # только гейт и деплой
python scripts/export/shots_live.py             # скриншоты живого сайта
```

## Важные напоминания
- Не начинать контент до закрытия 5 блокирующих проблем
- Все строки Sitemap в robots.txt отвечают 404, приоритет 1
- meta description = «Description» на главной и в блоге, приоритет 2
- 5 H1 на главной, приоритет 3
- Нет canonical и нет Schema, приоритет 4 и 5
- Картинки: один GIF 3,4 МБ, 11 из 15 тяжелее 200 КБ
- Em-dash в текстах заменять на запятые или переписывать фразу, а не
  прогонять регуляркой
