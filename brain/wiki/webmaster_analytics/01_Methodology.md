## 1. Статусы страниц (ApiSearchEventEnum / IndexingStatusEnum)

### SEARCHABLE — «В поиске»
- Страница в индексе и показывается в выдаче
- **Целевой статус** для всех важных страниц
- Источники попадания: обычный обход, Яндекс.Метрика, IndexNow, Sitemap

### DOWNLOADED — «Загруженные»
- Робот скачал страницу (код 2xx/3xx/4xx/5xx)
- Не означает попадание в поиск
- Подстатусы: `DOWNLOADED_2XX`, `DOWNLOADED_3XX`, `DOWNLOADED_4XX`, `DOWNLOADED_5XX`

### DUPLICATE — «Дубликат»
- Страница дублирует уже проиндексированную
- **Действие:** указать предпочтительный URL через:
  - 301 редирект на основную версию
  - `rel="canonical"` атрибут
  - Настройку `Clean-param` в robots.txt для параметров
- В API: `DUPLICATE` с полем `target_url` — адрес оригинала

### LOW_DEMAND — «Низкий спрос / Низкая ценность»
- Алгоритм решил: страница не интересна пользователям
- Причины: нет контента, дубликат известных страниц, контент не подходит под интент
- **Автоматически перепроверяется** — может вернуться в поиск
- **Действие:** улучшить контент, добавить уникальность, E-E-A-T сигналы

### BAD_QUALITY / LOW_QUALITY — «Низкое качество»
- Страница удалена из результатов по специальному алгоритму качества
- Если алгоритм найдёт страницу релевантной — вернёт автоматически
- **Действие:** глубокая переработка: экспертность, структура, факты, таблицы

### HTTP_ERROR — «Ошибка HTTP»
- Ошибка при доступе: 5xx, таймаут, соединение
- **Действие:** проверить сервер/хостинг, если доступно — запросить переобход

### REDIRECT_NOTSEARCHABLE — «Редирект не в поиске»
- Страница делает редирект, индексируется цель (`RedirectTarget`)
- **Действие:** проверить качество целевой страницы, убрать цепочки редиректов (>1)

### REDIRECT_SEARCHABLE — «Редирект в поиске»
- Страница делает редирект, но сама в поиске (редко, для коротких URL)

### CLEAN_PARAMS — «Исключена по Clean-param»
- Робот обработал директиву `Clean-param` в robots.txt
- **Действие:** отредактировать robots.txt если страница должна быть в поиске

### NO_INDEX — «Запрещено noindex»
- Метатег `robots: noindex` или HTTP заголовок `X-Robots-Tag: noindex`

### OTHER — «Другое / Нет актуальных данных»
- Робот не имеет свежих данных
- **Действие:** запросить переобход через «Переобход страниц»

### PARSE_ERROR — «Ошибка парсинга» (в экспорте страниц)
- Робот скачал, но не смог разобрать HTML/контент
- Причины: битый HTML, кодировка, тяжёлый JS, блокировка ресурсов
- **Действие:** проверить валидность HTML, доступность CSS/JS, server-side rendering

## 2. Индексация и переобход

### Как попасть в индекс быстрее:
1. **Sitemap.xml** — актуальный, поданный в Вебмастер
2. **IndexNow** — мгновенное уведомление об изменениях
3. **Яндекс.Метрика** — сигнал от первого визита пользователя
4. **Внутренняя перелинковка** — новые страницы от индексированных
5. **Приоритетный переобход** — до 20 URL/сутки в Вебмастере

### Квоты переобхода:
- Стандарт: ~20 URL/день через форму
- IndexNow: без лимитов (но нужен API ключ)
- Sitemap: робот сам решает частоту

## 3. Анализ поисковых запросов

### Разделы Вебмастера:
| Раздел | Назначение |
|---|---|
| **Статистика запросов** | Все запросы за период: показы, клики, CTR, средняя позиция |
| **Статистика страниц** | Посадочные страницы: показы, клики, CTR по URL |
| **Мониторинг запросов** | Динамика позиций по выбранным фразам (ежедневно) |
| **Расширенная аналитика по URL** | По каким запросам приходят на конкретные страницы |
| **Подбор запросов и анализ рынка** | Конкуренция, частотность, региональность (Беларусь, КЗ, Турция) |

### Ключевые метрики:
- **Показы (Impressions)** — сколько раз сайт показан в выдаче
- **Клики (Clicks)** — переходы на сайт
- **CTR** = Клики / Показы × 100%
- **Средняя позиция** — взвешенная по показам
- **Видимость** — доля запросов в ТОП-10/ТОП-3

## 4. Структура сайта в Вебмастере

Раздел «Индексирование → Структура сайта» показывает:
- **Индексировано** — страниц в базе Яндекса
- **Загружено** — страниц, которые робот скачал
- **В поиске (searchable)** — страниц, реально выдаваемых

**Коэффициент индексации** = `searchable / indexed × 100%`
- Норма: 60%+ для качественных сайтов
- <30% — проблемы с качеством/дублями/техникой

## 5. Алгоритм анализа для этого проекта

### Шаг 1: Парсинг всех экспортов
- `pages.csv` — статусы всех 717 URL
- `events.csv` — история ADD/DELETE (754 события)
- `queries_pos.csv` — ежедневные позиции (7 дней)
- `queries_avg.csv` — средние позиции за период
- `structure.csv` — агрегаты по разделам

### Шаг 2: Классификация страниц
```
SEARCHABLE + quality title/meta → ✅ OK
SEARCHABLE + "Каталог"/"Description" → ⚠️ ТЕМПЛАТ (нужен фикс)
DUPLICATE → 🔴 Канонизация нужна
PARSE_ERROR → 🔴 Технический аудит HTML/JS
REDIRECT_NOTSEARCHABLE → 🟠 Проверить цель редиректа
LOW_DEMAND/BAD_QUALITY → 🟠 Контент-аудит
HTTP_ERROR → 🔴 Сервер/хостинг
```

### Шаг 3: Кластеризация запросов
- Группировка по семантике (LDA/ручная)
- Назначение интента: commercial, informational, navigational, transactional
- Маппинг на существующие/потенциальные URL

### Шаг 4: Gap-анализ
- Запросы в ТОП-20 без целевой страницы
- Запросы с падающими позициями
- Конкуренты по ключевым кластерам (через «Подбор запросов»)

### Шаг 5: План действий
- Технические фиксы (приоритет: PARSE_ERROR, DUPLICATE, HTTP_ERROR)
- Контентные фиксы (LOW_DEMAND, шаблонные title/meta)
- Новые лендинги (коммерческие запросы без страниц)
- Статьи (информационные запросы, LOW_DEMAND темы)

## 7. Ограничения данных

1. **Период данных:** только 7 дней (14-20.09.2026) — нет сезонности
2. **CTR/показы/клики есть за те же 7 дней** (семантика файлов проверена кросс-чеком 2026-09-23: показы, позиции и клики разложены по трем файлам, CTR посчитан)

4. **Нет разбивки по устройствам** — десктоп и мобила обобщены
5. **Нет гео-разбивки** — только общая выдача (для локального бизнеса важно)
